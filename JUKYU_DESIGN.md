# Jukyu Design

Date: 2026-05-14

`jukyu.etzhayyim.com` is the global supply-demand System-of-Systems layer. It does not replace domain actors such as `naphtha-supply.etzhayyim.com`; it orchestrates them, normalizes their outputs, runs common stress propagation, ranks company exposure, and emits target-company signals.

## Product Goal

Answer three questions quickly:

1. Which companies are likely to be constrained by a supply-demand imbalance?
2. Where in the supply chain does the pressure originate, and what alternative chain is feasible?
3. Which evidence is observed, inferred, stale, or missing?

Jukyu supports better balance decisions and early warning. It does not claim unilateral control over world markets.

## System-of-Systems Graph

### Vertex

- `vertex_jukyu_supply_node`: normalized supply/demand node for facility, country, product, company, logistics hub or downstream buyer.
- `vertex_jukyu_balance_observation`: observed supply, demand, inventory, balance and price by domain/country/product/time.
- `vertex_jukyu_company_exposure`: company-level exposure generated by Pregel.
- `vertex_jukyu_pregel_run`: resident propagation run ledger.
- `vertex_jukyu_notification_signal`: signal outbox for target companies.

### Edge

- `edge_jukyu_supply_dependency`: physical, contractual, logistics or substitutable supply dependency.
- `edge_jukyu_company_operates_node`: company operates, owns, buys from or sells through a node.
- `edge_jukyu_exposure_triggers_signal`: traceability from exposure to signal.

### MV / IDX

- `mv_jukyu_global_balance`: global domain/country/product balance.
- `mv_jukyu_supply_chain_trace`: normalized traversal graph.
- `mv_jukyu_company_exposure_rank`: ranked company exposure.
- `mv_jukyu_notification_outbox`: pending target-company signals.
- indexes cover domain/country/product lookup, operator/company lookup, edge src/dst traversal, exposure ranking and notification delivery.

## UIUX

The default screen is an analyst cockpit.

| Region | Purpose |
|---|---|
| Left rail | Domain, geography, commodity, product family, company watchlist |
| Top controls | Scenario, time window, run Pregel, confidence filter, compare baseline |
| Center canvas | Supply-chain graph and map lane overlay |
| Right inspector | Selected node/company risk, facts, inferred pressure, evidence URLs |
| Bottom timeline | Cargoes, maintenance, closures, price changes, news/disclosure signals |

Views:

- **Balance**: country/product supply, demand, balance, utilization and price.
- **Chain**: node-link graph of source, terminal, factory, logistics hub, derivative and downstream buyer.
- **Companies**: ranked exposure table with score, confidence, affected products, evidence and notification status.
- **Scenario**: run disruption simulations such as port closure, cargo delay, war-risk lane shock, plant outage, price spike or demand surge.
- **Evidence**: source list, freshness, reliability, extraction status and unresolved claims.

Interaction rules:

- Clicking a company highlights every upstream supply lane and downstream product exposure.
- Clicking a lane shows quantity, lead time, dependency weight, substitution difficulty and affected nodes.
- Clicking a stress score opens the score decomposition.
- Analyst can pin a node/company into a watchlist; Pregel then treats it as an explicit seed or sink.
- UI labels inferred results as `inferred`; it must not present Pregel output as observed fact.

## MCP Design

MCP server: `jukyu-mcp`

Transport:

- UI -> SvelteKit proxy -> AgentGateway MCP -> LangServer pod
- LangServer pod owns DB credentials and graph writes
- MCP responses are JSON with stable schemas; large graph responses are paginated

Tools:

- `jukyu.queryBalance`
- `jukyu.querySupplyChain`
- `jukyu.rankCompanyExposure`
- `jukyu.runStressPropagation`
- `jukyu.explainNode`
- `jukyu.upsertSignal`
- `jukyu.exportBrief`
- `jukyu.notifyCompany`
- `jukyu.normalizeDomainAdapter`


## Pregel Design

Graph: `jukyu_global_equilibrium_v1`

Source topology:

- domain adapters supply `nodes`, `edges`, `balance`, `cargo`, `price`, `inventory`, `signals`
- for naphtha, topology starts with `mv_naphtha_supply_chain_trace`
- normalized topology is read from `mv_jukyu_supply_chain_trace`

State table:

- `vertex_langgraph_state`
- key pattern: `jukyu:<domain>:<country>:<run_id>:<node_id>`

State:

```json
{
  "runId": "jukyu.global.naphtha.20260514T000000Z",
  "domain": "naphtha",
  "nodeId": "naphtha-node:chiba-cracker",
  "nodeType": "steam_cracker",
  "countryCode": "JP",
  "operatorDid": "did:web:mitsuichemicals.com",
  "observed": {
    "capacityTonnesDay": 2800,
    "demandTonnesDay": 3400,
    "cargoTonnes": 35000,
    "priceUsdTonne": 690.5
  },
  "pressure": {
    "supply": 0.0,
    "demand": 0.0,
    "price": 0.0,
    "downstream": 0.0,
    "structural": 0.0
  },
  "riskScore": 0.0,
  "confidence": 0.0,
  "evidence": []
}
```

Message:

```json
{
  "src": "naphtha-node:jurong-terminal",
  "dst": "naphtha-node:chiba-cracker",
  "edgeType": "supply_link",
  "commodityCode": "NAPH-L",
  "capacityTonnesDay": 2800,
  "shockType": "cargo_delay",
  "pressureDelta": 0.22,
  "confidence": 0.74,
  "evidence": []
}
```

Supersteps:

1. Normalize domain observations into Jukyu nodes, dependency edges, balance observations and shocks.
2. Seed observed balance, price, cargo, inventory and manual/news shock signals.
3. Propagate upstream supply pressure through physical, contractual, logistics and substitution edges.
4. Apply demand absorption at producing sites, logistics hubs, warehouses, consumers and downstream plants.
5. Fan out downstream pressure to derivative products, components, industries and companies.
6. Aggregate node scores to company exposure by `operatorDid`, `owner_did`, legal entity and watchlist.
7. Write notification signals with severity, confidence, evidence and recommended action.

Score:

```text
risk =
  0.30 * supply_pressure
+ 0.20 * demand_pressure
+ 0.20 * price_pressure
+ 0.20 * downstream_pressure
+ 0.10 * structural_pressure
```

Confidence:

```text
confidence =
  min(1.0,
    0.30 * source_freshness
  + 0.25 * source_reliability
  + 0.20 * graph_connectivity
  + 0.15 * cargo_or_price_observation
  + 0.10 * corroboration_count
  )
```

Halting:

- max 8 supersteps by default
- stop if max company risk delta < 0.03 for two consecutive supersteps
- stop downstream fanout at low-confidence nodes unless explicitly requested

## Notification Signals

`vertex_jukyu_notification_signal` is an outbox, not a direct mailer. Delivery-specific actors route signals to company actors, email, inbox, API webhook or human review.

Signal severity:

- `critical`: immediate supply disruption likely; action recommended within hours
- `high`: material imbalance or substitution need
- `medium`: watchlist and procurement review
- `low`: informational signal with weak confidence

Every signal must include:

- target company DID
- risk score and confidence
- source domain and product family
- affected supply-chain path
- evidence JSON
- recommended action

## Resident Equilibrium Loop

Cadence:

- every 15 minutes: global balance scan and Pregel propagation
- hourly: domain adapter normalization
- event-driven: high-severity manual/news shock, cargo update, price spike or inventory update
- notification loop: read `mv_jukyu_notification_outbox`, route signals to target company actors or configured channels

The loop improves observability, early warning and routing of feasible substitution actions so companies can reduce harmful imbalance.

## Initial Domain Adapter

Naphtha adapter:

- reads `mv_naphtha_country_balance`, `mv_naphtha_cargo_flow`, `mv_naphtha_price_latest`, `mv_naphtha_supply_chain_trace`
- writes normalized `vertex_jukyu_supply_node`, `edge_jukyu_supply_dependency`, `vertex_jukyu_balance_observation`
- maps company exposure through `operator_did` and legal-entity joins when available

## Implementation Phases

1. Register actor and MCP design.
2. Add global `vertex_jukyu_*`, `edge_jukyu_*`, `mv_jukyu_*` schema.
3. Add naphtha adapter queries using existing `mv_naphtha_*`.
4. Add `jukyu_global_equilibrium_v1` Pregel primitive in LangServer.
5. Build cockpit UI with graph canvas, company table, inspector and evidence timeline.
6. Add non-naphtha adapters only after they satisfy the MCP response schema.
7. Activate target-company signal routing through MCP/company actors.
