# etzhayyim-project-jukyu — Global Supply Demand System

> **Runtime**: K8s pod-side LangServer / MCP / LangGraph Pregel. Cloudflare edge is only UI and proxy.

`jukyu.etzhayyim.com` analyzes supply-demand imbalance and supply-chain stress across commodities, products, companies and countries. It is a System-of-Systems actor: domain actors remain source-of-truth, while Jukyu normalizes their outputs, runs global Pregel propagation, ranks company exposure, and emits target-company signals.

## UX Contract

The first viewport is the operational cockpit, not a landing page:

- left rail: domain selector, geography, commodity/product, company watchlist
- top bar: scenario, time window, confidence threshold, refresh state
- main canvas: supply-chain graph with stressed nodes, cargo lanes and derivative propagation
- right inspector: selected company/node evidence, risk score, demand/supply balance, open questions
- bottom timeline: cargo arrivals, planned maintenance, closures, price changes, disclosure/news signals

No DB I/O runs in the edge UI. UI calls the MCP surface, which dispatches to pod-side LangServer.

## Graph Contract

- `vertex_jukyu_supply_node` — normalized site/company/product/country supply or demand node.
- `vertex_jukyu_balance_observation` — observed supply, demand, inventory, balance and price.
- `vertex_jukyu_company_exposure` — ranked company exposure generated by Pregel.
- `vertex_jukyu_pregel_run` — resident propagation run ledger.
- `vertex_jukyu_notification_signal` — target-company signal outbox.
- `edge_jukyu_supply_dependency` — physical, contractual or substitutable supply dependency.
- `edge_jukyu_company_operates_node` — company-to-site/node ownership or operation.
- `edge_jukyu_exposure_triggers_signal` — exposure-to-notification traceability.

## LLM Integration

Models route through `llm.etzhayyim.com` (LiteLLM gateway → murakumo-serve fleet).

| Role | Model | Trigger |
|---|---|---|
| Extraction / scenario | `qwen3-30b` | `scenarioText` set on `/runs`; `POST /extract/shocks` |
| Narrative generation | `gemma-4-e4b-it` | `withLLM: true` on `/runs`; `POST /export/brief` |

Graph inputs (`/runs` or `/cron/equilibrium` body):

| Field | Type | Default | Effect |
|---|---|---|---|
| `withLLM` | bool | `false` | Enable `enrich_signals` node — generates LLM title/body/action for top-N signals |
| `scenarioText` | string | `null` | Free-text scenario → `parse_scenario` node extracts shock seeds before Pregel |
| `shockSeeds` | `{domain:country → 0–1}` | `{}` | Manual shock seeds (bypasses LLM parsing) |

Env vars (pod): `JUKYU_LLM_URL`, `JUKYU_LLM_API_KEY`, `JUKYU_LLM_EXTRACTION_MODEL`, `JUKYU_LLM_NARRATIVE_MODEL`, `JUKYU_LLM_TIMEOUT`, `JUKYU_LLM_ENRICH_MAX`.

The resident 15-min equilibrium loop runs with `withLLM=false` (no LLM overhead).

## Pregel

Primary graph: `jukyu_global_equilibrium_v1`

DAG: `init_run → read_balance → read_chain → read_transport_context → parse_scenario → propagate ←loop→ write_signals → enrich_signals → read_outbox`

Initial adapter: naphtha over:

- `mv_naphtha_country_balance`
- `mv_naphtha_cargo_flow`
- `mv_naphtha_price_latest`
- `mv_naphtha_supply_chain_trace`
- `vertex_langgraph_state`

Global SoS surface:

- `mv_jukyu_global_balance`
- `mv_jukyu_supply_chain_trace`
- `mv_jukyu_company_exposure_rank`
- `mv_jukyu_notification_outbox`

Pregel state must separate observed facts from inferred pressure and confidence. UI should display confidence and evidence gaps next to every ranking.

## Resident Behavior

The actor runs every 15 minutes. It reads global imbalance MVs, runs bounded Pregel propagation, ranks company exposure, writes notification signals, and lets delivery-specific actors send or route the signal. Jukyu supports better equilibrium decisions; it does not claim unilateral control over world markets.
